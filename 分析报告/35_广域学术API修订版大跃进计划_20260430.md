# 第六名后“大跃进计划”修订版：广域学术 API 与高增益提分路线

作者：**Manus AI**  
日期：2026-04-30  
适用仓库：`bisai`  
当前底座：`submit_v44_del_var_con_cross.json`，已知 A 榜分数 **0.4514**

## 一、结论先行：从“只做极小减法”升级为“离线大召回、线上小提交”

上一版计划的核心纪律是正确的：在已经到第六名且 `v44_del_var_con_cross` 达到 0.4514 的阶段，不能再把未经验证的大批量加法、LLM 直接生成或多关系类型混合提交作为主线。新的广域学术检索并没有否定这一点，反而进一步证明：生物医学关系抽取的高分系统通常不是单一提示词或单一模型带来的，而是由 **数据中心化处理、实体角色方向性、候选生成、弱监督证据、关系级后处理和保守集成** 共同构成的流水线。[1] [2] [3]

修订后的战略应从“只能保守减法”变成 **两层速度差**：线下必须大幅扩展候选发现能力，使用学术论文、外部弱监督、关系特定问答和实体类型标记寻找潜在漏项；线上提交仍然保持极小步、可归因、可回滚。换句话说，真正适合当前位置的“大跃进”不是一次性提交大改版，而是建立一个可以持续生产高精度原子实验的 **候选证据工厂**。

> **修订版核心公式**：  
> 大幅提分潜力 = 离线候选召回扩大 × 方向角色纠错 × 证据表筛选 × v44 底座小步融合。  
> 线上提交必须继续遵守“一假设一提交”，但离线候选搜索不能再停留在手工删低频关系。

## 二、广域学术检索改变了哪些判断

本次检索使用开放网页、论文页面、GitHub 工具仓库以及 Crossref、OpenAlex、Semantic Scholar 等学术 API 进行扩展。检索结果显示，BioBERT、BioRED、BioREx、方向性增强、关系特定 QA、LLM-IE、弱监督与噪声标签学习是当前可迁移性最高的几个方法簇。[2] [4] [5] [6] [7] [8]

| 原判断 | 广域检索后的修正 | 对当前仓库的影响 |
| :--- | :--- | :--- |
| 只能继续做极小减法 | 线上仍做极小提交，但离线必须建立高召回候选层 | 新增 `candidate_evidence_table.csv`、方向矩阵、LLM-QA 复核，而不是只改 json |
| LLM 直接生成候选可能带来大涨 | LLM-IE 研究显示生成式 RE 容易高召回低精度，必须先用实体对预过滤和结构化审查 | LLM 只能做争议样本审阅器、候选解释器和证据打分器，不能直接主导提交 |
| 方向问题只是 v44/v45 的局部现象 | 方向性增强论文把实体角色方向性作为 BioRE 的核心问题 | `GENE-LOI-MRK`、`MRK-LOI-GENE`、`CROSS-CON-VAR` 等应建立方向混淆矩阵 |
| 外部工具暂时无用 | BioREx 说明异构数据融合和 schema 对齐可显著改善 BioRED 关系抽取 | 外部工具可作为弱标注和证据排序器，但不能直接输出天池提交 |
| 多模型投票可以继续扩大 | 历史仓库已显示多模型加法多次掉分，噪声标签研究也提示一致性不是充分条件 | 投票结果必须加入“历史涨跌、类型频次、方向、样本簇”多维过滤 |

## 三、学术方法到当前仓库的可执行迁移

### 3.1 Data-centric 异构数据融合：不是重训大模型，而是建候选证据表

BioREx 论文报告了通过异构生物医学关系抽取数据集整合来提升 BioRED 任务表现的 data-centric 路线，API 检索也显示该方向与 BioRED、BioCreative 等任务高度相关。[2] [5] 对当前 `bisai` 来说，直接重训 BioREx 或照搬 PubTator schema 风险较高，因为天池关系类型更偏作物育种实体体系。但其核心思想可以迁移为：把外部工具、训练集频次、历史版本一致性、方向矩阵和 LLM-QA 判断统一成 **候选证据表**。

| 字段 | 含义 | 用途 |
| :--- | :--- | :--- |
| `sample_idx` | A 榜样本序号 | 保证每个实验可定位 |
| `relation_key` | head、tail、label、span、type 的唯一键 | 防止重复候选与错误覆盖 |
| `in_v44` | 是否存在于 0.4514 底座 | 区分删除、换向、新增 |
| `train_type_freq` | 训练集中同类型三元关系频次 | 判断低频 FP 风险 |
| `reverse_type_freq` | 训练集中反向关系频次 | 判断方向错误风险 |
| `history_presence` | 该关系出现在 v36、v41、v44、v45 等版本中的次数 | 构造“遗忘/稳定性”代理指标 |
| `llmqa_judgement` | 关系特定 QA 的结构化判断 | 只作为证据，不直接提交 |
| `external_evidence` | BioREx、PubTator、STRING 等外部证据 | 低权重辅助排序 |
| `action` | keep/delete/swap/add/review | 进入原子提交队列 |

该表是修订版计划的第一优先级。没有它，所谓“大量提分”只能靠猜；有了它，离线可以大胆扩候选，而线上仍然保持极小提交。

### 3.2 Directionality：当前最有可能稳定涨分的高优先级路线

方向性增强论文指出，BioRED 原始标注缺少实体角色方向性，而方向性对生物关系网络至关重要；论文补充了大规模 directionality annotations，并用多任务模型同时识别关系、novel findings 与实体角色。[3] 这与仓库的经验高度一致：`v44_del_var_con_cross` 的涨分已经证明 **方向纠错/删除方向异常关系** 比盲目加法更可靠。

本次脚本分析得到：训练集中 `GENE-LOI-MRK` 仅 2 条，而反向 `MRK-LOI-GENE` 为 22 条；v44 中仍存在 5 条 `GENE-LOI-MRK`，同时已有 2 条反向关系。这是目前最明确的方向异常族。

| 关系类型 | v44 数 | 训练频次 | 反向类型 | 反向训练频次 | 修订后处理 |
| :--- | ---: | ---: | :--- | ---: | :--- |
| `GENE-LOI-MRK` | 5 | 2 | `MRK-LOI-GENE` | 22 | 第一优先级：删除版与换向版成对提交 |
| `CROSS-CON-VAR` | 7 | 28 | `VAR-CON-CROSS` | 8 | 已有涨分线索，谨慎做补回对照 |
| `TRT-AFF-GENE` | 1 | 3 | `GENE-AFF-TRT` | 177 | 单条人工 QA，不做整类修改 |
| `BM-USE-MRK` / `MRK-USE-BM` | 3 / 1 | 7 / 3 | 双向都存在 | 复杂 | 暂不整包删除，需样本证据 |

因此，下一轮 v46 的第一组实验不应是“大范围删除所有低频关系”，而应是围绕 `GENE-LOI-MRK` 做 **删、换、删换组合** 三个原子提交，并结合关系特定 QA 给出每条样本证据。

### 3.3 QA + Entity Type Markers：把 LLM 从“生成器”降级为“裁判”

BioNLP 2023 的实体类型标记与关系特定 QA 论文指出，当多个实体对共享实体时，普通 QA 很容易抽错目标关系，因此需要把实体类型和关系模板显式注入问题。[6] LLM-IE 工具论文也强调，在关系抽取前应使用 `possible_relation_types_func` 预过滤实体对；其 multi-class RE 结果呈现高召回、低精度特征，这与当前仓库中 v38/v43 直接 LLM 加法掉分的经验一致。[7]

对当前仓库，推荐的 QA 模板不应是“文本里有哪些关系”，而应是严格判别式：

| 关系族 | 判别模板 | 输出限制 |
| :--- | :--- | :--- |
| `GENE-LOI-MRK` | 文本是否直接说明 **某个 marker/SNP 定位或链接到某个 gene**，还是说明 gene linked to marker？请只判断候选 head/tail 方向是否符合训练集语义。 | `supported / reversed / unsupported / ambiguous` |
| `GENE-CON-TRT` | 文本是否直接说明基因包含、控制或构成该 trait/stress/light response，还是只是 promoter elements respond to stimulus？ | 只判别，不新增 |
| `QTL-AFF-BIS` | 文本是否表达 QTL/locus 影响病害/pathotype，还是 resistance locus against pathotype 的自然语言误标？ | 只判别样本簇 |
| `ABS-AFF-GENE` | 文本是否说明非生物胁迫影响基因表达/功能，而不是同句共现？ | 仅用于微量新增候选 |

该机制的价值在于把 LLM 的作用约束在 **解释和判别**，避免它凭常识自由生成关系。所有 LLM-QA 结果必须落入候选证据表，再由脚本生成提交。

## 四、v46/v47 实验队列：从高确定性纠错到高上限补召回

根据 `academic_to_experiment_mapping_20260430.md` 的脚本分析，当前最值得执行的实验队列如下。优先级依据不是论文热度，而是 **仓库历史验证 + 训练分布异常 + 样本簇集中度 + 学术方法支持** 的综合结果。

| 优先级 | 实验名 | 修改对象 | 预计收益 | 风险 | 提交纪律 |
| ---: | :--- | :--- | :--- | :--- | :--- |
| 1 | `v46_direction_gene_loi_mrk_delete` | 删除 5 条 `GENE-LOI-MRK` | 高精度降 FP；与训练方向分布一致 | 若测试真值保留 gene→marker 会损失 FN | 只删该族，不叠加其他修改 |
| 2 | `v46_direction_gene_loi_mrk_swap` | 将 5 条换为 `MRK-LOI-GENE` | 可能同时降 FP、补 FN | 换向错误会新增 FP | 必须与删除版对照提交 |
| 3 | `v46_gene_con_trt_cluster372_del` | 删除样本 372 的 4 条 `GENE-CON-TRT` | 低频样本簇 FP 清理 | 若官方把 promoter cis-elements 视作 gene CON trait，会掉分 | 单样本簇，不删整类 |
| 4 | `v46_qtl_aff_bis_cluster50_del` | 删除样本 50 的 3 条 `QTL-AFF-BIS` | 清理低频病害/pathotype 误关系 | 关系可能被官方接受 | 单样本簇 |
| 5 | `v46_lowfreq_var_oci_gst_del` | 删除 2 条 `VAR-OCI-GST` | 训练频次仅 1，可能为 OCI 误用 | 语义可能确实是材料发生阶段 | 两条合并或逐条提交 |
| 6 | `v46_llmqa_lowfreq_gate` | 对训练频次 ≤2 的 v44 关系做 QA 打分 | 建立下一批高置信删除/换向候选 | LLM 判断偏差 | 不直接提交，只生成证据表 |
| 7 | `v47_abs_aff_gene_micro_add` | 从 v44 漏项中找 1—3 条 `ABS-AFF-GENE` | 唯一仍可能产生正收益的微量加法 | 新增 FP 风险高 | 必须具备 QA + 训练模式 + 文本触发词三重证据 |
| 8 | `v47_external_weak_evidence` | BioREx/PubTator/STRING 证据排序 | 长期上限提升 | schema 不匹配 | 只作为候选排序特征 |

这里尤其要避免一个常见误区：低频不等于必删。`BM-USE-TRT`、`BIS-AFF-BIS`、`TRT-LOI-CHR` 等虽然训练频次不高，但可能有清晰语义；若整包删除，很容易重复 v45 类候选的风险。因此 v46 必须优先做 **样本簇级**，而不是类型级一锅端。

## 五、工程改造计划：把仓库从“提交文件堆”改造成“实验流水线”

目前仓库已经积累了大量提交文件、分析报告和候选生成脚本，这说明历史经验很丰富，但也带来一个问题：新方案如果继续只靠人工复制 json，很快会失去可追溯性。修订版建议新增三类工程文件。

| 新增产物 | 建议路径 | 作用 | 产出格式 |
| :--- | :--- | :--- | :--- |
| 候选证据表生成器 | `工具脚本/build_candidate_evidence_table.py` | 汇总 v44、训练频次、反向频次、历史版本稳定性、LLM-QA 和外部证据 | `.csv` + `.md` |
| 方向矩阵报告 | `分析报告/direction_confusion_matrix_20260430.md` | 自动统计每个关系族的正反向分布 | Markdown 表格 |
| v46 原子提交生成器 | `工具脚本/make_v46_atomic_candidates.py` | 从证据表按实验名生成 json 和 zip | `数据/A榜/submit_v46_*.json` |
| LLM-QA 审阅缓存 | `分析报告/llmqa_lowfreq_cache.json` | 保存每条候选的判别结果、理由和模板版本 | JSON |
| 提交账本 | `分析报告/submission_ledger_20260430.md` | 记录每次提交假设、差异、得分和下一步 | Markdown |

其中 `submission_ledger` 必须从下一次提交开始强制维护。每个提交只回答一个问题，例如“删除 `GENE-LOI-MRK` 是否涨分”，而不是把多个方向修正、低频删除和新增候选混在一起。

## 六、具体 72 小时执行路线

第一天的重点是 **把 v46 第一批原子候选生成出来**。先基于现有脚本输出的方向矩阵，生成 `v46_direction_gene_loi_mrk_delete`、`v46_direction_gene_loi_mrk_swap`、`v46_gene_con_trt_cluster372_del` 和 `v46_qtl_aff_bis_cluster50_del` 四个提交。每个提交只修改一个关系族或一个样本簇，提交前必须生成 diff 表，提交后立即把分数写入账本。

第二天的重点是 **构建 LLM-QA 证据层**。对训练频次 ≤2 的 v44 关系逐条生成关系特定问题，强制返回 `supported / reversed / unsupported / ambiguous`。只有当 QA 结果与训练分布、方向矩阵、历史掉分经验同时一致时，才进入下一轮原子候选。若 QA 与训练分布冲突，则标记为人工复核，不提交。

第三天的重点是 **尝试有限补召回**。只有在前两天确认删除/换向路径的有效性后，才允许做 `ABS-AFF-GENE`、`CROP-CON-GENE` 或其它高频稳定类型的微量新增。新增每次不超过 3 条，必须满足文本触发词明确、实体类型稳定、训练集同型关系频次高、QA 判定 supported 四个条件。

| 时间窗 | 目标 | 可交付物 | 是否允许提交 |
| :--- | :--- | :--- | :--- |
| 0—6 小时 | 生成 v46 原子提交 | 4 个 json/zip + diff 报告 | 允许，按优先级逐个提交 |
| 6—18 小时 | 建立 QA 审阅缓存 | `llmqa_lowfreq_cache.json` | 不允许直接提交 |
| 18—36 小时 | 根据首批分数更新策略 | `submission_ledger` | 允许提交第二批原子候选 |
| 36—72 小时 | 微量补召回 | 1—2 个新增型候选 | 仅在纠错路径验证有效后允许 |

## 七、红线与止损规则

第六名阶段最危险的不是没有新方法，而是把新方法用错。广域学术检索给出的明确警告是：LLM、弱监督和异构数据融合都会扩大候选空间，但如果没有精度闸门，会把噪声一起放大。[7] [8] 因此必须设定止损规则。

| 红线 | 禁止原因 | 替代做法 |
| :--- | :--- | :--- |
| 禁止一次新增超过 5 条关系 | 历史 LLM 加法已多次掉分 | 新增候选拆成 1—3 条原子提交 |
| 禁止整包删除所有低频关系 | 低频中存在真关系，v45 风险已经显现 | 按样本簇和方向异常拆分 |
| 禁止 LLM 直接输出最终提交 | 生成式 RE 高召回低精度 | 只输出 QA 判别和证据理由 |
| 禁止多假设混合提交 | 无法归因，分数回撤后无法定位 | 一假设一提交，一提交一账本 |
| 禁止追随外部 biomedical schema 直接映射 | 天池作物育种 schema 与 BioRED/PubTator 不完全一致 | 外部证据只做低权重排序 |

## 八、最终建议：先冲 v46 方向纠错，再开 v47 候选工厂

综合仓库历史、当前分数、学术检索和脚本统计，我建议立即把上一版计划修订为：**v46 先用方向性与样本簇低频清理拿确定性收益，v47 再引入 LLM-QA 和外部弱监督作为候选工厂**。这样既保留了第六名后需要的保守提交纪律，又不会错失学术方法带来的上限空间。

最重要的第一步是提交 `GENE-LOI-MRK` 的删除版与换向版对照。该关系族同时满足三个条件：v44 中存在、训练频次极低、反向训练证据强。这是当前最符合学术方向性理论与仓库历史规律的高优先级实验。若它涨分，应继续沿方向混淆矩阵推进；若它掉分，则说明官方测试集可能保留了与训练集不同的方向口径，下一步应回到样本簇删除和 QA 审阅，而不是扩大换向。
